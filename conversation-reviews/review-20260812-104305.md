1. **Pydantic structured output 字段名不匹配导致校验失败**

   > 原问题：`langchain_v1.2/chapter06_structured_output/01-StructuredOutput.ipynb:1-21` 用户选中 Person 模型代码，执行报 `Field required` 错误

   关键点：
   - LLM（qwen-max）返回 `{'name': '张三', 'age': 30, 'job': 'AI架构师'}`，但 Pydantic 模型期望 `user_name` 和 `occu`
   - qwen-max 的 json_schema 模式对字段名约束不够强，会自行"翻译"字段名
   - 解决方案：换用 `method='function_calling'`、换用 qwen3.7-plus、或使用更常见的英文字段名

2. **Python 函数参数中的 `/` 和 `*` 分隔符作用**

   > 原问题：在方法的参数列表中声明的 `/` 和 `*` 是干嘛的

   关键点：
   - `/` — 位置参数分隔符，左侧参数只能按位置传，不能用关键字
   - `*` — 关键字参数分隔符，右侧参数只能用关键字传，不能按位置
   - `/` 和 `*` 之间的参数两种方式都可以

3. **大数据核心技术问题：MapReduce、大数据目标、流式计算原理**（合并 3 个问题）

   > 原问题：MapReduce在大数据里应用是不是很广泛
   > 原问题：大数据主要处理什么问题
   > 原问题：流式计算的原理是什么，为什么这么快

   关键点：
   - MapReduce 是大数据思想基石，但实际工程已被 Spark、Flink 替代，磁盘 IO 太重、编程模型原始
   - 大数据本质：用分布式思路解决单机扛不住的存储和计算问题，核心是"分而治之"和"移动计算而非移动数据"
   - 流式计算快的原因：数据在内存中流动不落盘、程序常驻无启动开销、增量计算不重算、窗口机制化整为零

4. **LangChain `@tool` 装饰器生成 StructuredTool 对象不可直接调用**

   > 原问题：`langgraph/src/07_ReAct实现.ipynb` 工具调用报 `TypeError: 'StructuredTool' object is not callable`

   关键点：
   - `@tool` 装饰器将函数封装为 `StructuredTool` 对象，附带 name、description、args_schema 等元信息
   - `StructuredTool` 不支持 `()` 直接调用，需用 `.invoke(args_dict)`
   - 封装的目的是让 LLM 能理解工具的名称、用途和参数结构

5. **LangChain 工具参数描述的多种声明方式**

   > 原问题：在声明工具的时候，对于参数的描述只能写在doc_string里吗？

   关键点：
   - Docstring（Google 风格）— 直观，函数和描述在一起
   - `Annotated[type, ..., "描述"]` — 简洁，不用写 docstring
   - `args_schema=PydanticModel` — 完整校验能力，复杂场景首选
   - 简单工具用 Annotated 或 docstring，参数多、有校验逻辑的用 args_schema

6. **LangGraph 动态路由 `draw_mermaid_png()` 报错：`NoneType` 与 `str` 比较**（合并 2 个问题）

   > 原问题：`langgraph/src/07_ReAct实现.ipynb:35-36` `graph.get_graph().draw_mermaid_png()` 报 `TypeError: '<' not supported between instances of 'NoneType' and 'str'`
   > 原问题：为什么只在动态路由的时候报这个错，静态路由时不会

   关键点：
   - 根本原因：`Command(goto=...)` 和 `add_conditional_edges` 同时作用于同一个节点，产生冲突
   - `Command` 本身就是动态路由（节点自己决定 goto），不需要 `add_conditional_edges`
   - 两者同时存在时 LangGraph 内部构建边元数据产生 `None` 值，排序时报错
   - 修复：使用 `Command` 时删掉 `add_conditional_edges`

7. **LangGraph 动态路由中 `AIMessage` 对象不支持下标访问**

   > 原问题：`langgraph/src/07_ReAct实现.ipynb:1-65` 动态路由执行报 `TypeError: 'AIMessage' object is not subscriptable`

   关键点：
